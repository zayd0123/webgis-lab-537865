# Lab 3, Part 2 — the QGIS steps, and what to screenshot

`lab3/data/district_points.geojson` is already in the repository, generated by
`lab3/make_point_layer.py`, which reproduces QGIS's **Point on Surface**
algorithm. Part 2 of the handout is nonetheless marked on the *centroid
comparison*, so the QGIS comparison still has to be seen and screenshotted.
This file is the recipe.

## The answer, and how to see it

> **Sibi** (Balochistan) is the district whose centroid falls outside it. The
> centre of mass sits **0.0240° (about 2.7 km) outside** the boundary, in
> **Harnai**.
>
> `lab3/Report/checkpoint2_sibi_centroid_vs_point_on_surface.png` is the same
> finding drawn from the data. The QGIS version is the one to submit.

Sibi is a crescent: a long arm reaches north-east, so the balance point of the
shape falls in the notch on the western side rather than in the body of the
district. No other district out of 160 does this — the next closest are Nagar
(0.0093° inside) and Nankana Sahib (0.0119° inside).

## Steps

1. Open QGIS and drag in `lab3/data/districts.geojson`.
2. **Vector ▸ Geometry Tools ▸ Centroids** on that layer. Leave it in EPSG:4326.
3. **Vector ▸ Geometry Tools ▸ Point on Surface** on that layer too.

   *QGIS 3.40 and later have these under **Vector ▸ Geometry Tools ▸
   Centroids** / **Point on Surface**. On older builds Point on Surface is in
   the Processing Toolbox (`native:pointonsurface`) — search <kbd>Ctrl</kbd>+<kbd>Alt</kbd>+<kbd>T</kbd> for "point on surface".*

4. Select the Centroids layer, open the attribute table, and sort or filter the
   `district` column for **Sibi**. Note the coordinate, or use **Zoom to
   Layer**.
5. Style the two point layers differently — a red cross for Centroids, a blue
   dot for Point on Surface — so both are visible at once.
6. **Zoom in tightly on Sibi.** You should see the red cross sitting outside
   the black boundary, in Harnai, and the blue dot inside.
7. Screenshot. That is **Checkpoint 2**, together with the size and feature
   count below.

## Why the script does not simply use shapely's `representative_point()`

`representative_point()` is a *point on surface* too, and most GIS software
treats the two as interchangeable. They are not the same point:

| | QGIS Point on Surface | shapely `representative_point()` |
|---|---|---|
| Method | centre of the bounding box, then nearest point on the polygon if that falls outside | **pole of inaccessibility** — the centre of the largest inscribed circle |
| Largest disagreement here | **0.877° on Gwadar** | |
| Districts where they differ appreciably | Gwadar, and the coastal districts with deep inlets | |

Gwadar's coastline is so concave that the two land almost a degree apart. The
screenshots for this lab come from QGIS, so `make_point_layer.py` reproduces
QGIS's algorithm, and every district point in the repository is the point the
QGIS tool would have produced.
